# 0004. HMAC-SHA256 for API keys, Argon2id for passwords

**Status** Accepted

## Context

Both are secrets presented on authentication, so the instinct is to hash both
the same way, with the slow algorithm, because slow is safe.

That instinct is wrong here, and applying it uniformly costs real latency for
no security gain.

## Decision

Two different algorithms for two different threat profiles.

**Passwords — Argon2id.**

```python
PasswordHasher(time_cost=3, memory_cost=65536, parallelism=4,
               hash_len=32, salt_len=16, type=Type.ID)
```

Passwords are low entropy, chosen by humans, reused across sites and present in
dictionaries. Slow hashing is the entire defence. The cost is paid once per
login.

**API keys — HMAC-SHA256 under a server-side pepper.**

```python
hmac.new(settings.api_key_pepper.encode(), plaintext.encode(), hashlib.sha256)
```

An API key is 32 characters from a 62-character alphabet generated by a
CSPRNG: about 190 bits. There is no dictionary, no reuse, no human pattern, and
no feasible brute force to stretch against. Argon2 would add 50-100 ms to
**every authenticated request** and buy nothing, because there was no
brute-force surface to protect.

The pepper is server-side only, never in the database, so a database dump does
not let an attacker verify a guessed key offline. Comparison is always
`hmac.compare_digest`.

## Alternatives rejected

**Argon2 for both.** Consistent, and 50-100 ms slower per request for a
guarantee that was already free. At 240 requests a minute per principal that is
a material throughput cost.

**Plain SHA-256 with no pepper.** Fast and constant-time, but a database dump
alone lets an attacker verify guesses offline. The pepper costs nothing and
removes that.

**Store keys encrypted rather than hashed.** Reversible, which means something
somewhere can reveal a key. Hashing means nothing can.

## Cost

Two code paths and a rule that has to be understood rather than followed, which
is exactly the kind of thing a future contributor "fixes" into consistency.

Mitigations: the rule is stated at the top of
[`app/core/security.py`](../../backend/app/core/security.py), and
`tests/unit/test_security.py::test_keys_are_hmac_hashed_not_argon2` fails if
someone unifies them.

The second cost is harder. Rotating `API_KEY_PEPPER` invalidates every stored
hash, and there is no re-peppering without the plaintext — which is gone by
design. A pepper rotation means rotating every API key in the system.

That is the correct trade for a value that never has to be read back, but it
has to be planned for before it is needed. See
[secrets](../security/secrets.md).
